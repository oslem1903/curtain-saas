## 1. 🔴 P0 GÜVENLİK AÇIĞI — canlı üretimde doğrulandı

### Firmalar arası fotoğraf sızıntısı (Supabase Storage)

**Bu "kodda şüpheli görünüyor" değil — canlı veritabanında çalıştırılıp kanıtlandı.**

| Kontrol | Sonuç |
|---|---|
| `POST /storage/v1/object/list/measurement-photos` (anon anahtar) | **HTTP 200** |
| Dönen ilk seviye klasörler | **5 farklı firma UUID'si** |
| Örnek keşfedilen yol | `24657cb3-…/24d38332-…/photo-1787511346760-inl7ggm.png` |
| `GET /storage/v1/object/public/measurement-photos/<yol>` — **hiçbir anahtar/oturum yok** | **HTTP 200**, `image/png`, **2.104.652 bayt** |
| Aynı durum `catalog-images`, `logos`, `visual-previews` için | **Üçü de HTTP 200** |

Anon anahtar **her kurulumun içinde gömülüdür** — yani uygulamayı indiren herkeste
vardır. Sonuç: bir firma, diğer tüm firmaların ölçü fotoğraflarını listeleyip
indirebilir. Oturum açmak bile gerekmiyor.

### Buna karşılık TABLO tarafındaki RLS DOĞRU çalışıyor

Anon rolle sorgulandı, **hepsi 0 satır döndü**:

```
companies 0 · company_members 0 · profiles 0 · customers 0 · orders 0
order_items 0 · payments 0 · appointments 0 · notifications 0 · suppliers 0
supplier_transactions 0 · installer_transactions 0 · installer_earnings 0
catalog_code_photos 0 · order_installments 0
rpc/get_current_auth_context -> []      storage bucket listesi -> []
```

Yani sorun **yalnızca** `storage.objects` tarafında.

### Yapılanlar

**A) Kod (UYGULANDI, diskinizde):** Görseller artık kalıcı public URL ile değil,
**kısa ömürlü imzalı (signed) adreslerle** gösteriliyor.

| Dosya | Ne yapıldı |
|---|---|
| `src/utils/storagePath.ts` *(yeni)* | Saf yol çözümleme (public/sign URL → bucket + nesne yolu) |
| `src/utils/storageUrl.ts` *(yeni)* | İmzalı adres üretimi, önbellek, hata hâlinde orijinale düşme |
| `src/components/SecureImage.tsx` *(yeni)* | `<img>` yerine geçen, adresi imzalayan bileşen |
| `src/components/SecureLink.tsx` *(yeni)* | Fotoğraf "yeni sekmede aç" bağlantıları için aynısı |
| 10 ekran | **18 `<img>` + 5 `<a href>`** imzalı adrese çevrildi |
| `src/context/AuthContext.tsx` | Oturum değişiminde imzalı adres önbelleği temizleniyor |

**Geçiş güvenliği:** İmzalı adresler public bucket'ta da çalışır ve imzalama
başarısız olursa kod orijinal adrese geri düşer. Bu yüzden kod değişikliği
**tek başına** yayınlanabilir; hiçbir görsel kırılmaz.

**B) Veritabanı (⛔ UYGULANMADI — onayınızı bekliyor):**
`supabase_storage_tenant_isolation.sql`

- 4 bucket `public = false`
- `storage.objects` üzerinde firma bazlı SELECT/INSERT/UPDATE/DELETE politikaları
- Betiğin başında ön kontrol: `my_company_ids()` / `is_super_admin()` yoksa
  **hiçbir şey değiştirmeden** durur
- Sonunda doğrulama komutları + ROLLBACK bölümü

> **Uygulama sırası önemli:** ① yeni uygulama sürümünü yayınlayın → ② kullanıcıların
> güncellediğini doğrulayın → ③ SQL'i çalıştırın. Sıra bozulursa eski sürümdeki
> kullanıcılarda tüm fotoğraflar kırık görünür.

**Onay verirseniz SQL'i çalıştırıp sonucu aynı yöntemle (anon listeleme → 0 kayıt,
public indirme → 400/404) kanıtlayabilirim.**

## 5. Bu turda dikkat edilen regresyon riskleri

| Risk | Nasıl önlendi |
|---|---|
| `VisualPreviews` canvas çizimi `ref`li `<img>`e bağlı; `SecureImage` ref'i iletmez | O iki görsel **düz `<img>` bırakıldı**; doku adresi ayrı state'te imzalanıp verildi |
| `photoUrl` aslında `blob:` (yerel önizleme) — imzalanmamalı | `immediateSrc()` ile render sırasında ayrıştırılıyor |
| `src` değişince eski görselin imzalı adresi kısa süre görünebilir | İmzalı adres, ait olduğu `src` anahtarıyla birlikte saklanıyor |
| Effect içinde senkron `setState` (2 lint hatası çıktı) | Bileşenler yeniden yazıldı; lint tekrar **0 hata** |
| `SecureLink` adres hazır değilken boş sekme açabilir | `href` yokken tıklama engelleniyor |

   Chromium'da 390 px genişlikte yapıldı — **gerçek telefon sonucu değildir.**
